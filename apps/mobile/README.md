# Ludo Lovers Mobile App

This directory contains the Android-first Flutter foundation for Ludo Lovers.

## Current status

- The home screen uses the locked Ludo Lovers palette and dark premium theme.
- The board preview renders the current 15×15 board fixture and supports sample-pawn selection.
- The Local Game Lab connects the local rules engine to a board-backed prototype: roll, highlight legal pawns, move, capture/bonus-turn behavior, turn changes, restart and completion.
- Engine, route, controller and widget tests cover the current local prototype.
- **Important release gate:** the physical route and safe-cell mapping are provisional. The board factory intentionally reports `isGameplayReady = false`; do not promote this prototype to release/competitive gameplay until the route is reconciled with the approved straight-on board reference and all four seat paths are validated.
- CI runs Dart formatting, Flutter analysis, automated tests and an Android debug APK build. A green CI run proves these checks passed for that commit; it does not replace visual validation on a real Android device.
- The Android platform folder is generated by CI rather than committed. A debug APK is uploaded as a workflow artifact when the workflow succeeds.

## Validate locally

Install the Flutter stable SDK and Android toolchain. From this directory run:

```sh
flutter pub get
dart format --output=none --set-exit-if-changed .
flutter analyze
flutter test
flutter build apk --debug
```

## Implementation priorities

### Priority 1 — Board correctness gate
1. Keep the v1 geometry contract explicit: the only non-orthogonal transitions are the documented one-cell diagonals at indexes 4, 17, 30 and 43; these are documented provisional topology, not visual approval.
2. Compare the 52-cell route, all four start cells, home lanes and safe cells against the approved board reference, including the four star coordinates.
3. Correct route coordinates, player-relative path rotations and painter mapping together if visual review identifies a mismatch.
4. Keep acceptance tests for every seat's wraparound, lane entry, exact finish, overshoot, safe cells, legal destinations, and visual-topology contract.
5. Only set gameplay readiness to true when the approved reference and test evidence support it.

### Priority 2 — Local gameplay polish after route approval
1. Add clear destination feedback and restrained pawn movement animation driven by engine state.
2. Improve small-screen layout and accessibility semantics for dice, current turn and legal pawns.
3. Expand deterministic end-to-end widget coverage for capture, no-legal-move rotation, bonus rolls and match completion.
4. Validate a full match on an Android device before calling the experience release-ready.

### Later
Online identity, friends, private rooms, chat and multiplayer require a separate secure backend and authoritative game server. Never trust a client to determine online dice, moves, winners or coin balances.

## Board fixture and rules boundary

The canonical route fixture is located at
`lib/features/game/domain/board/classic_ludo_board_fixture.dart`.
It remains separate from rendering. The engine owns rules and legal moves; the renderer presents engine state and must not independently implement game rules.

## Assets

Do not replace or recreate the official Ludo Lovers logo. Confirm the actual logo asset file and its license/location before adding it under `assets/branding/` and registering it in `pubspec.yaml`.

## Secrets

Never commit Supabase service-role keys, private keys, passwords or production tokens. Client configuration must use only publishable/public project values and still be protected by database and backend access controls.
